ALLOWABLE POST-ANALYZER CONTROLLER DECISIONS

The controller must issue exactly one of the following:

ACCEPT
  Condition: Analyzer finds no blocking defects. All WARN items reviewed and found non-blocking. All DISAGREE items adjudicated in favor of the current draft. Draft is ready to proceed to human approval gate.
  Next step: Proceed to human approval (Step 13 in the master flow). Do not implement until human approval is obtained.

MODIFY
  Condition: Analyzer identified a non-blocking issue or a DISAGREE item where the controller determines a targeted correction is warranted. Full regeneration is not required.
  Next step: Specify exact modifications. Apply modifications. Controller confirms modified draft. Proceed to human approval only after confirmation.
  Note: Modification must not add blocked modules or emit held fields. If either was the issue, issue REJECT instead.

REJECT
  Condition: Analyzer identified a blocking defect — e.g., a held field was emitted, a blocked module is present, content was invented, or a DISAGREE item reveals a prior reviewer error that constitutes a blocking defect.
  Next step: Draft is discarded. Return to Prompt 01 for regeneration. Run full review sequence again.

DEFER
  Condition: Post-analyzer review reveals an external condition that prevents proceeding — e.g., a Phase 0 freshness question raised by the analyzer, an evidence conflict that needs owner resolution, or a fingerprint concern.
  Next step: Suspend the run. Document the blocking condition. Resume only when resolved.

HUMAN_REVIEW_REQUIRED
  Condition: The analyzer raised an ambiguity or edge case that requires package owner judgment before the run can continue.
  Next step: Escalate to the package owner. Do not proceed until the owner resolves and explicitly authorizes continuation.

PATCH_REQUIRED
  Condition: The analyzer identified a specific, targeted defect that can be corrected without full regeneration, but the correction must be reviewed as a formal patch — not an informal modification.
  Next step: Document the exact patch required. Apply the patch. Run Prompt 02 (QA) and Prompt 04 (validator) on the patched draft before returning to Prompt 14 for confirmation.

- If the analyzer's position reveals a non-blocking concern: issue MODIFY or note as documented warning

NON-AUTHORIZATION STATEMENT

The controller post-analyzer decision does not approve the draft for production. An ACCEPT decision from Prompt 14 means the draft is ready to proceed to the human approval gate. It does not mean the draft is approved for implementation. Explicit human approval is required before any implementation handoff. The controller does not self-approve. The controller does not mutate source truth.
